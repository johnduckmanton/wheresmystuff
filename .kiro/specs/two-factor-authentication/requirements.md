# Requirements Document

## Introduction

Add TOTP-based two-factor authentication (2FA/MFA) to the existing Cognito-based login system. Users will be able to set up an authenticator app (e.g., Google Authenticator, Authy) from their profile page, verify TOTP codes during sign-in, and enable or disable MFA on their account. The infrastructure change enables TOTP as an optional MFA method on the Cognito User Pool via the SAM template.

## Glossary

- **User_Pool**: The AWS Cognito User Pool resource defined in template.yaml that manages user authentication
- **TOTP**: Time-based One-Time Password, a 6-digit code generated by an authenticator app using a shared secret
- **MFA_Setup_Flow**: The frontend workflow where a user associates a TOTP authenticator app with their account by scanning a QR code and verifying a code
- **Sign_In_Page**: The existing React component at `/signin` that handles user authentication
- **Profile_Page**: The existing React page at `/profile` where users manage their account settings
- **Authenticator_App**: A third-party application (e.g., Google Authenticator, Authy) that generates TOTP codes
- **QR_Code**: A scannable image encoding the TOTP secret URI, used to register the secret in an Authenticator_App
- **MFA_Challenge**: A Cognito sign-in step requiring the user to provide a TOTP code after entering valid credentials
- **SAM_Template**: The AWS SAM template.yaml file that defines the application's cloud infrastructure

## Requirements

### Requirement 1: Enable TOTP MFA on the Cognito User Pool

**User Story:** As a system administrator, I want TOTP-based MFA enabled on the Cognito User Pool, so that users can optionally secure their accounts with an authenticator app.

#### Acceptance Criteria

1. THE SAM_Template SHALL configure the User_Pool with `MfaConfiguration` set to `OPTIONAL` to allow per-user MFA enrollment
2. THE SAM_Template SHALL include `SOFTWARE_TOKEN_MFA` in the User_Pool `EnabledMfas` list
3. THE SAM_Template SHALL remove the production-only gating condition so that TOTP MFA is available in all environments
4. THE SAM_Template SHALL retain the existing `ALLOW_USER_SRP_AUTH` and `ALLOW_USER_PASSWORD_AUTH` explicit auth flows on the User_Pool client

### Requirement 2: TOTP Setup Flow

**User Story:** As a user, I want to set up TOTP-based MFA from my profile page, so that I can secure my account with an authenticator app.

#### Acceptance Criteria

1. WHEN a user initiates MFA setup from the Profile_Page, THE MFA_Setup_Flow SHALL call the Amplify `setUpTOTP` API to generate a TOTP secret
2. WHEN a TOTP secret is generated, THE MFA_Setup_Flow SHALL display a QR_Code encoding the TOTP secret URI that the user can scan with an Authenticator_App
3. WHEN a TOTP secret is generated, THE MFA_Setup_Flow SHALL display the TOTP secret as a copyable text string for manual entry into an Authenticator_App
4. WHEN the user submits a valid 6-digit TOTP code, THE MFA_Setup_Flow SHALL call the Amplify `verifyTOTPSetup` API to verify the code and complete association
5. WHEN the TOTP association is verified, THE MFA_Setup_Flow SHALL call the Amplify `updateMFAPreference` API to set TOTP as the preferred MFA method for the user
6. IF the user submits an invalid TOTP code during setup, THEN THE MFA_Setup_Flow SHALL display an error message indicating the code is incorrect and allow the user to retry
7. WHEN MFA setup completes, THE MFA_Setup_Flow SHALL display a confirmation message indicating MFA is active on the account

### Requirement 3: MFA Challenge During Sign-In

**User Story:** As a user with MFA enabled, I want to be prompted for my TOTP code after entering my password, so that my account is protected by two-factor authentication.

#### Acceptance Criteria

1. WHEN the Cognito sign-in response returns a `CONFIRM_SIGN_IN_WITH_TOTP_CODE` step, THE Sign_In_Page SHALL display a TOTP code input form
2. THE Sign_In_Page SHALL accept a 6-digit numeric TOTP code from the user
3. WHEN the user submits a valid TOTP code, THE Sign_In_Page SHALL call the Amplify `confirmSignIn` API and navigate to the home page on success
4. IF the user submits an invalid TOTP code, THEN THE Sign_In_Page SHALL display an error message and allow the user to retry
5. IF the TOTP verification session expires, THEN THE Sign_In_Page SHALL redirect the user back to the credentials form with an informative message
6. WHEN the sign-in response returns a `CONTINUE_SIGN_IN_WITH_TOTP_SETUP` step, THE Sign_In_Page SHALL redirect the user to the MFA_Setup_Flow instead of showing an unsupported error

### Requirement 4: MFA Management from Profile

**User Story:** As a user, I want to enable or disable MFA from my profile page, so that I can control the security level of my account.

#### Acceptance Criteria

1. WHEN the Profile_Page loads, THE Profile_Page SHALL query the current MFA preference for the authenticated user using the Amplify `fetchMFAPreference` API
2. WHILE MFA is not enabled for the user, THE Profile_Page SHALL display an option to set up TOTP MFA
3. WHILE MFA is enabled for the user, THE Profile_Page SHALL display the MFA status as active and provide an option to disable MFA
4. WHEN the user chooses to disable MFA, THE Profile_Page SHALL call the Amplify `updateMFAPreference` API to remove TOTP as the preferred MFA method
5. WHEN MFA is disabled, THE Profile_Page SHALL update the displayed MFA status to reflect the change
6. WHEN the user chooses to enable MFA and has not previously set up TOTP, THE Profile_Page SHALL initiate the MFA_Setup_Flow

### Requirement 5: TOTP Setup During Forced MFA Enrollment

**User Story:** As a user who is required to set up MFA during sign-in, I want to complete the TOTP setup inline, so that I can access my account without being blocked.

#### Acceptance Criteria

1. WHEN the sign-in response returns a `CONTINUE_SIGN_IN_WITH_TOTP_SETUP` step, THE Sign_In_Page SHALL retrieve the TOTP setup details from the sign-in response
2. THE Sign_In_Page SHALL display a QR_Code and copyable secret string for the user to register in an Authenticator_App
3. WHEN the user submits a valid 6-digit TOTP code, THE Sign_In_Page SHALL call the Amplify `confirmSignIn` API with the TOTP code to complete setup and sign-in
4. IF the user submits an invalid TOTP code during forced setup, THEN THE Sign_In_Page SHALL display an error message and allow the user to retry
5. WHEN forced TOTP setup and verification succeed, THE Sign_In_Page SHALL navigate the user to the home page
